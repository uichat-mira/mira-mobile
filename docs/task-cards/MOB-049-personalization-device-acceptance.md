## 背景

「设置 → 个性化」页在上游一直是静态样板：控件无交互、设置不持久化。PR #142 补全了全部控件接线并接入设备本地持久化（`localKeyValueStore`，key `mira.mobile.personalization.v1`），自动化证据（typecheck / lint / Jest / 双平台构建 / AI Review / SonarCloud）已在 PR CI 通过。

但按仓库规则，**自动化不能替代真机交互与持久化验收**。本卡把剩余的人工验收项显式列出，验收通过前 PR 不得合入 `dev`。

## 已知边界（先读，避免误报）

1. **设置项暂不影响 AI 对话语气**。本卡验收的是"界面可交互 + 设备本地记住"，不是"AI 按个性化说话"。后者是后续接线卡的挂账项，测出"AI 没变幽默"不算缺陷。
2. **设置是设备本地的**，不跨设备同步、不上传 Host——这是与主题设置一致的既有合同，不是缺陷。
3. **自定义指令是防抖保存**：停顿约 0.5 秒后才写存储；输入后立刻杀进程（0.5 秒内）可能丢最后一小段输入，属预期行为。按 ✓ 返回或停顿后再杀进程则不丢。
4. **存储写入失败提示**与**读取失败锁定**两个场景人工难以稳定注入，见用例 10，无法执行可标注"未验证"，不阻塞 PASS。

## 验收用例

以下 1–9 在 **Android 真机** 必测；iOS 至少覆盖 1、2、4、6、8。凡"保持 / 记住"类结论，一律以**杀掉 App 进程后重新打开**的状态为准，仅退出页面返回不算。

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 1 | 入口 | 设置 → 我的 Mira → 个性化 | 进入个性化页，标题正确；返回按钮与右上 ✓ 均可返回 |
| 2 | 语调选择与持久化 | 点「基本风格和语调」→ 选「专业严谨」→ 杀进程重开 | 弹出三选项且当前项带 ✓；副标题回显；重开后仍为「专业严谨」 |
| 3 | 提高亲和度 | 拨动开关 → 杀进程重开 | 开关状态即时变化且重开后保持 |
| 4 | 特征增删与上限 | a) 添加「讲话简短」b) 再添加同一条 c) 添加至满 12 条 d) 点 ✕ 删除一条 e) 弹窗内清空输入 | a) 列表出现该行、计数 1/12；b) 行内提示「该特征已存在」且弹窗不关；c) 添加入口变禁用（半透明）、副标题「已达上限 12 条」、点击无弹窗；d) 该行消失、计数回退、入口恢复；e) 「添加」按钮禁用 |
| 5 | 快速回答 | 拨动开关 → 杀进程重开 | 状态保持 |
| 6 | 自定义指令持久化 | 输入一段文字 → 停 1 秒 → 杀进程重开；再用例：输入后直接按右上 ✓ 返回 → 重开 | 两种方式文字均保留 |
| 7 | 混合回归 | 同时设置语调 + 亲和 + 特征 + 快速回答 + 指令 → 杀进程重开 | 全部保持，无一项回默认 |
| 8 | 外观联动 | 切深色模式、切换重点色后查看本页 | 各控件（开关色、禁用态、错误条）在深浅色下均可读、无穿帮 |
| 9 | 键盘与弹窗交互 | 打开添加特征弹窗输入；Android 按系统返回键 | 输入框不被键盘遮挡；返回键可关闭弹窗且不误触「添加」 |
| 10 | 读取失败锁定（可选，开发者执行） | 调试环境将存储值改为非法 JSON 或注入 get 抛错 → 进页面 | 页面锁定编辑（半透明 + 不可点）、顶部显示错误与「重试」；重试成功后恢复可编辑且数据正确。人工无法注入时标注「未验证」 |
