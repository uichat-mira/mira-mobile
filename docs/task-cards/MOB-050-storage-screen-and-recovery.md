## 背景

「设置 → 通用 → 存储」一行历史上是占位：没有 actionId、没有导航、没有数据来源。本卡把它从占位升级成真实功能：

- 展示客户端在本地的真实占用（按类目拆分），明示哪些数据是设备本地、哪些在远端。
- 提供两个一次性的本地维护动作：
  1. **清理已提交拾言原始录音**：删除 `status === 'submitted'` 的拾言录音本地原始文件。云端 R2 归档、提交指针、历史与任务状态全部不动。
  2. **清空本地 UI 状态**：仅重置外观、个性化、线程本地置顶 / 未读，并清空拾言 Cloud API 地址。**拾言草稿与已提交录音索引、本地 Provider 配置与会话保留**；设备配对凭据、Provider API Key、拾言 R2 / 历史记录不受影响。
- 分类来源、UI 状态、清理按钮的边界全部来自纯函数模块 `src/screens/deviceStorageUsage.ts`，可注入、可测。

## 边界（先读，避免误报）

1. 本页只统计 **客户端本地占用**，不含 Mira Host / 拾云端远端数据。
2. 设备安全存储（`deviceCredentialStore` / `providerCredentialStore` / `desktopCredentialStore`）里的任何凭据、API Key、刷新令牌都不会出现在统计中，也不会被「清空本地 UI 状态」清除。
3. 「清理已提交拾言原始录音」**只删除本地原始音频文件**，不修改 `mira.shiyan.submissions.v1` 与 `mira.shiyan.local-captures.v1` 的元数据；因此拾言历史 / 任务状态 / Cloud R2 归档 / GitHub Destination 全部不变。如需清空未提交草稿，到「拾言 → 全部记录」逐条删除。
4. Native 录音模块缺失时（开发态或 Mock store），「已提交拾言原始录音」字节数按 `fileSizeBytes` 兜底，UI 仍展示但不可清理——这是为了避免在无法触及真实文件时假装成功。模块可用性探测**不得**调用真实 `fileInfo`：Android/iOS 原生层会把路径限制在录音目录内，任意探测路径都会被判为越界，从而把「模块可用」误判成「模块缺失」。
5. 「清空本地 UI 状态」**不触碰**拾言草稿与索引（`mira.shiyan.local-captures.v1` / `mira.shiyan.submissions.v1`）。若清掉这些索引，磁盘上的原始录音会失去唯一索引，后续无法通过「清理已提交拾言原始录音」找到它们（CodeRabbit 复审发现，2026-09-26 收口）。本地 Provider 配置与会话同样保留（仅作占用展示）。
6. 主题 provider 的 hydrate 状态在清空后会在下一次进入「个性化」/「外观」时回到默认值，不需要重启 App。
7. **杀进程口径**：所有"保持 / 清理 / 重置"类结论一律以**杀掉 App 进程后重新打开**的状态为准；「清空本地 UI 状态」与「清理已提交录音」本身即时生效，验收时在操作完成并回到设置页后杀进程重开再核对，不需要在清空前重启。

## 安装包来源（合并前 dev release 不含本功能）

## 验收用例

凡"保持 / 清理 / 重置"类结论，一律以**杀掉 App 进程后重新打开**的状态为准，仅退出页面返回不算。

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 1 | 入口 | 设置 → 通用 → 存储 | 进入存储页，标题正确；返回按钮可返回；存储行右侧 chevron 可点 |
| 2 | 占用展示 | 正常 App + 已有部分个性化 / 至少一条已提交拾言 | 顶部"设备存储占用"显示非零；分类区有"外观与重点色 / 个性化 / 拾言草稿与提交记录 / 已提交拾言原始录音"等可见行；每行副标题显示字节数 |
| 3 | 刷新按钮 | 在统计显示后，点右上 ↻ | 短暂 loading → 重新统计，类别字节数变化（如有新增操作后）正常反映 |
| 4 | 读取失败（可选） | 调试环境让 storage get 抛错 → 进页面 | 顶部行副标题显示失败提示 + 重试；分类区显示带错误图标的占位卡片 + 重试按钮；点重试成功则恢复 |
| 5 | 清理已提交录音 | 录音 → 确认 → 提交到 Cloud → 杀进程重开 → 进存储 → 点"清理"→ 确认 | Alert 显示"已清理 N 条…"；存储页重新统计后"已提交拾言原始录音"类目字节数归 0；"已提交录音 N 条"变为 0；回到拾言 → 全部记录，所有已提交记录仍存在并可点开 |
| 6 | 草稿不受影响 | 录音 → 仅保存草稿（不提交）→ 杀进程重开 → 清理已提交录音 | 草稿仍存在，文件未被删；本地草稿的大小字节数（如果未来计入草稿文件占用）保持不变 |
| 7 | 清空本地 UI 状态 | 设置好主题 / 个性化 / 置顶若干线程 → 进存储 → 点"清空本地 UI 状态" → 确认 → 杀进程重开再核对 | Alert 显示清除 N 个键（全失败时显示"清空失败"）；重开后外观 / 个性化 / 线程置顶未读均回到默认；**拾言草稿与已提交记录索引保留**；**Local Provider 配置与会话保留**；Mira Host 仍处于已配对状态；拾言历史 / 已提交任务仍在 |

| 8b | 拾言索引保留 | 录制一条 → 提交到 Cloud → 进存储清空本地 UI 状态 → 杀进程重开 → 进「拾言 → 全部记录」 | 该记录仍在列表；点开可正常进入详情；随后「清理已提交拾言原始录音」仍能定位并清理它的本地文件（索引未被清空） |
| 9 | 配对凭据不被清空 | 已配对 Mira Host 状态显示"已连接" | 进存储清空 → 回到主列表，连接状态仍为"已连接"，重新进 Host 配对页仍能正常 resume，不会被踢回未配对 |
| 10 | 外观联动 | 切深色 / 切重点色后查看本页 | 卡片、按钮、说明卡在深浅色下均可读，按钮禁用态颜色清晰 |
| 11 | 键盘 / 弹窗交互 | 进存储后弹系统返回键 | 返回键回到设置页，不误触发任何清理操作 |

## Hard Constraints

- 没有真机证据不得标 PASS；不得用"模拟器看起来没问题"替代 Android 真机结论。
- 「保持 / 清理 / 重置」类用例（5、6、7、8、9）不得以"退出页面再看一眼"代替杀进程重开（口径见边界 7）。
- 用例 4（读取失败）人工难以稳定注入，可标注"未验证"，不阻塞 PASS。
- 发现失败时记录：设备型号、系统版本、包来源 / commit、复现步骤、截图或录屏；从最新分支开 fix，不在验收记录里直接宣称已修。

## Handoff

当前人工主验收面为 **Android 真机**。Android 核心“统计 / 清理 / 保留 / 重启后状态”路径通过，且自动化与双平台 CI build 绿色，即可进入 PASS 判断；iOS 普通共性路径由 iOS build / Simulator 证据覆盖，iOS 真机无设备时记 `validation gap`，不阻塞本卡。只有后续出现明确 iOS 原生存储差异时，才追加对应 iOS 真机专项。

用例 4 等需要故障注入的 developer-only 场景无条件时可标「未验证」，不要求真人构造异常。任一 Android 核心项 ❌ → 失败项回施工方修复，本卡重新进入待验收。
